# 🎭 剧场排练走位工具（Stage Blocking Tool）

一个面向剧场排练的轻量 Web 工具：在 **8 × 6 舞台网格**上设置演员起点，**逐拍**指定每位演员的「上 / 下 / 左 / 右 / 原地」动作，自动推演全部演员位置，标出走位冲突，并可基于当前推演生成**只读的排练场记报告快照**。

- 零第三方运行时依赖：后端只用 Node.js 内置模块，前端不用任何框架 / CDN / 账号
- 走位表自动保存在**浏览器本地**（localStorage），刷新或重启后可继续编辑
- 报告快照独立保存，生成后再编辑走位**不会**改动已生成的报告
- 一键 Docker 启动，默认访问 <http://localhost:3000>

---

## 一条命令启动（推荐：Docker）

前置条件：已安装 Docker（含 Compose 插件，Docker Desktop 或 Docker Engine ≥ 20.10 均可）。

```bash
# 在项目根目录（含 docker-compose.yml 的目录）执行
docker compose up --build
```

然后浏览器打开：

> **http://localhost:3000**

常用命令：

```bash
docker compose up -d --build   # 后台运行
docker compose logs -f         # 跟踪日志
docker compose restart         # 重启
docker compose down            # 停止并移除容器（镜像保留）
docker compose down --rmi local # 同时删除本项目构建出的镜像
```

健康检查：容器内置了 `/health` 探活（每 30 秒），也可手动验证：

```bash
curl http://localhost:3000/health   # → {"status":"ok"}
```

端口被占用时，修改 `docker-compose.yml` 中 `"3000:3000"` 的左侧端口（例如 `"8080:3000"`）后重新 `docker compose up -d`。

首次打开会自动载入一段示例走位（包含互换、碰撞、越界拦截三种情况），便于直接体验；清空后即为空白工程。

## 不用 Docker：本机 Node.js 直接运行

需要 Node.js ≥ 18（内置 node:http / node:fs，**无需 `npm install`**）：

```bash
npm start        # 等价于 node server.js
# 或
node server.js
```

打开 <http://localhost:3000> 即可。

## 使用说明

### 舞台坐标

- 网格 **8 列 × 6 行**，坐标显示为 `列-行`（如 `4-2` 表示第 4 列第 2 行）
- **第 1 行靠近观众席**（舞台下方），**第 6 行靠近上场方向**（舞台上方）
- 动作方向：**上 △**（行号 +1，远离观众）、**下 ▽**（行号 −1）、**左 ◁**（列号 −1）、**右 ▷**（列号 +1）、**原地 ·**

### 基本流程

1. 点击右侧「**＋ 添加演员**」，自动进入起点设置模式
2. 在舞台网格上点击一个格子，作为该演员的**起点**（再点同一格取消，按 `Esc` 或点行内 `◎` 退出模式）
3. 在底部「走位表」里，为每位演员的每一拍选择动作；也可以点「＋ 添加拍」增加拍数
4. 用顶部 **◀ ▶ / 进度条 / 播放按钮** 逐拍查看推演结果；键盘 `←` `→` 也可切拍

### 越界拦截

- 若某拍的动作会让演员走出 8×6 网格，该动作**立即被拦截**：下拉框回退、弹出提示（说明演员、拍、方向、所在格），该演员该拍**原地不动**
- 已保存的动作若因起点修改等原因变为越界，会在走位表中以**红框**标出，舞台对应格显示 ⛔ 角标，并出现在冲突列表中；改回合法动作后自动消失

### 冲突检测

| 类型 | 含义 | 舞台表现 |
| --- | --- | --- |
| 🔴 同拍同格 | 同一拍两位及以上演员位于同一格（第 0 拍起点重叠也会检测） | 红框高亮该格 |
| 🔁 相邻两拍互换 | 相邻两拍之间 A 与 B 正好交换格子（X→Y 且 Y→X），此类**不计为碰撞** | 两格橙色框 + 双向虚线箭头 |
| ⛔ 越界拦截 | 动作超出舞台边界被拦截 | 红框动作格 + ⛔ 角标 |

- 点击右侧冲突列表中的任意一条，会**自动跳到对应拍**，舞台上蓝色脉冲框标出对应格子，并在走位表中闪烁对应动作格
- 「定位下一个」按钮按拍顺序循环定位冲突；冲突数显示在标题红色徽标中

### 排练场记报告（只读快照）

右侧「**📋 排练场记报告**」面板用于把某一段走位固化成可打印、可归档的场记：

1. **选择拍次范围**：两个下拉框分别选择起止拍（可从「起点」开始；起止反转会自动纠正）
2. **选择演员**：点击演员胶囊勾选 / 排除（也可「全选 / 清空」），默认全部纳入
3. 点击「**📸 生成报告快照**」，弹层中显示报告：
   - **冲突汇总**：按拍次排序列出 🔴 同格 / 🔁 互换 / ⛔ 越界 三类冲突，含类型徽标、人数与格子坐标
   - **逐拍场记**：逐拍逐人列出本拍**动作**（如「▷ 右」）与**拍末坐标**；越界、同格、互换分别在行内以底色与标签标出，未设起点的演员显示「未设起点」
4. 每条冲突右侧的「**跳回第 N 拍**」按钮会关闭报告并把舞台定位到对应拍、复用主界面的蓝色脉冲定位；若生成后走位已被改过、现场冲突对不上，则仅跳到该拍并给出提示
5. 报告弹层提供：
   - **🖨 打印 / 存 PDF**：内置打印样式（`@media print`），只输出报告正文、浅色纸面排版，舞台与走位表不会进入打印稿
   - **⬇ 下载 JSON**：导出该份快照（文件名含生成时间），结构独立、可读，便于存档或转交
   - **🔄 按当前走位重新生成**：旧快照原样保留，另存一份新快照

**快照不可变**：报告在生成时把坐标、动作、冲突、演员名单、拍次范围全部拷贝为静态数据，之后无论怎么增删演员 / 改起点 / 改动作，已生成的报告都不会变化。报告列表会用「**走位已变更 / 与当前一致**」标记每份快照与当前走位（指纹）是否一致；打开旧报告时顶部也有同样的醒目提示。

- 报告保存在同一浏览器本地的独立键 `stage-blocking-reports:v1`，与走位存档 `stage-blocking:v1` 互不影响：**清空全部走位不会删除报告**，最多保留最近 30 份
- 走位存档结构完全未改动（仍是 `stage-blocking:v1`），旧版本数据可直接继续使用

### 数据保存与迁移

- 所有演员、起点、逐拍动作与当前查看的拍号，都会在每次修改后自动写入**该浏览器**的 localStorage（键名 `stage-blocking:v1`）
- 排练场记报告快照保存在独立键名 `stage-blocking-reports:v1`，最多保留最近 30 份；走位数据结构与旧版本完全兼容
- 刷新页面、重启容器都不会丢失；换浏览器 / 电脑不会同步（设计上完全本地、无后端数据库、无需任何账号）
- 「**导出 JSON**」可把走位表保存为文件；「**导入 JSON**」可在另一台机器继续编辑；报告弹层中可单独下载每份报告的 JSON
- 「清空全部」只清除本浏览器的走位存档，**不会**删除已生成的报告快照（报告列表内每条可单独删除）

## 项目结构

```
.
├── server.js            # Node 内置 http 静态服务器（含安全头、路径穿越防护、/health）
├── package.json         # 元信息与启动脚本（无第三方依赖）
├── public/
│   ├── index.html       # 页面结构（含报告生成面板与只读报告弹层）
│   ├── styles.css       # 剧场深色主题样式（含 @media print 打印样式）
│   └── app.js           # 全部业务逻辑：推演 / 冲突检测 / 报告快照 / 渲染 / 本地存储
├── test/
│   └── smoke.mjs        # 零依赖冒烟测试（移动、越界、碰撞、互换、数据规整、报告生成与快照不可变）
├── Dockerfile           # 基于 node:20-alpine 的生产镜像
├── docker-compose.yml   # 单服务编排，映射 3000 端口，含健康检查
└── README.md
```

核心推演函数 `simulate(actors, beats)` 与报告生成函数 `buildReport(state, sim, options)` 均为纯函数（位于 `public/app.js`）：前者输入演员与拍数，输出每拍位置、越界、碰撞、互换四类结果；后者输入走位状态与一次推演结果，输出自包含的只读报告快照；Node 环境下可直接 `require` 用于测试。

## 配置项（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | 监听端口；如改成其他端口，请同步调整 `docker-compose.yml` 的端口映射 |
| `HOST` | `0.0.0.0` | 监听地址 |

示例：`PORT=8080 node server.js`

## 技术说明 / 隐私

- 后端仅提供原生 HTML / CSS / JS 静态文件与 `/health` 健康检查，不收集、不上传任何数据
- 响应头设置 CSP（只允许同源资源）、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`
- 静态文件路径做了规范化与穿越校验
- 无需任何第三方账号、API Key 或外部服务
